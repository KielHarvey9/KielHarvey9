### 🎙️ JARVIS

**A personal AI assistant for Windows that you can talk to, and that asks before it touches anything important.**

Say "Jarvis" and talk, or just type. It answers questions, searches the web, and hands desktop work (opening apps, creating and editing files in folders I've approved) to a task agent called CODY.

- **Voice runs locally.** Wake word, speech recognition, and the spoken voice all run on the PC.
- **A policy layer sits between the AI and the computer.** File changes need on-screen approval, deleting files isn't possible, and one hotkey stops everything.
- **Memory stays on the machine.** History and memories are stored in an encrypted database. Private mode saves nothing, and Local Only mode sends nothing to the cloud.
- **It watches the bill.** Simple one-step tasks go to a fast, cheap model and harder work goes to a deeper one. Every reply's cost is logged. Fuller adaptive routing is in testing.

Private beta, tested daily on my own PC, with over 1,200 automated tests.

**Stack:** Python · PySide6 · Claude API · Porcupine · sherpa-onnx · Piper and Kokoro voices · SQLCipher · pytest

## How I build with AI

I don't write most of the code by hand. I focus on the parts I'm good at: defining the problem, writing the spec, deciding what "done" means, testing it like a customer would, and cutting features nobody needs.

- **Spec first.** Every project starts with a written spec and a briefing file, so each AI session works from the same facts.
- **Separate builder and reviewer.** On JARVIS, one AI model writes the code and a different one reviews it. Neither can merge or release. That's my job.
- **Measure it or say so.** If something hasn't been tested on real hardware, the docs say it hasn't.
- **Ship and fix.** RockReader is on version 0.7.360. A lot of what I know came from fixing what broke.

I also experiment with local models for work that shouldn't leave the machine.

## What I believe about software

- Understand the problem before you pick the tool.
- If people won't use it, it doesn't matter how clever it is.
- Software should fix something real.
- People who know an industry can now build the tools that industry needs. That used to take a dev team and a budget.
- The fastest way to learn is to build it, test it, and fix it.
